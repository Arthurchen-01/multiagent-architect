# 模式卡模板

> 用这个格式往 `references/pattern-library.md` 里加新模式。
> **填不满的卡不许入库** —— 尤其是「常见误判」和「验证实验」这两栏。

---

## 复制以下内容

```markdown
### P-NN 模式名 ｜类：<分解 / 状态 / 约束 / 不确定性 / 反馈 / 资源 / 故障 / 演化>

- **识别信号**：我在现场会**看到**什么？（具体到能一眼认出来，不要写「架构不好」这种）
- **底层机制**：为什么会这样？（机制层面的因果，不是「因为没写好」）
- **常见误判**：新手会以为是什么？会因此去做什么白工？
- **解决原则**：怎么处理？一句话能说清，且不依赖具体技术栈。
- **适用边界**：**什么情况下这条不成立？**（必须给出反例；给不出就不许入库）
- **验证实验**：**做什么最小实验能确认它成立？**（要能跑、能看结果，不要「多观察」）
- **案例**：哪次真实事故？（写清现象 + 查到什么；不要贴本机路径、IP、用户名）
```

---

## 入库前自检

- [ ] 「识别信号」是**看得见**的现象，不是判断结论。
- [ ] 「验证实验」是**可执行**的动作，不是「多想想」。
- [ ] 「适用边界」里写得出**反例**。
- [ ] 「案例」来自**真实事故**，不是编的。
- [ ] 没有和已有卡片**重复**（重复就合并，不要并排放两张）。
- [ ] 没有把**项目特定事实**写进卡里（那些属于项目文件）。

## 卡片的三条等级

| 等级 | 判据 | 怎么用 |
| :-- | :-- | :-- |
| **已证实** | 有可复现的验证实验，且跑过 | 可以直接按它做 |
| **待验证** | 有案例，但没做过区分性实验 | 用的时候**先做验证实验**再动手 |
| **猜想** | 只有直觉 | **不许单独使用**，只能用来生成假设 |
