# 汇报模板（工程图七段 + 人话 + 大图）

> 给用户的每份汇报都照这个来。
>
> **本项目（这台机器上）的权威版本**在项目库的《工程图式汇报》文件里；
> 本模板是它的**可携带精简版**，用于换到别的项目/别的机器时。两边冲突时以项目库那份为准。

---

## 两个要求叠在一起

- **七段是骨架**（下面的结构），**每段用人话写**（术语第一次出现必须当场翻译）。
- **结尾必须有「这在全局的哪里」** —— 没有它，读者不知道这事值不值得现在做。

**唯一判据**：随便抽一段出来，一个不懂这行的人能不能读懂？读不懂 = 重写。

---

## 复制以下内容

```markdown
# <标题>

## 〇、这个项目整体是什么
三条线/几大块，一句话带过。（读者要能对上位置）

## 一、目标
最终要交出去的东西。
| 交付物 | 用在哪 | 状态 |
| :-- | :-- | :-- |

## 二、生产线
用 ASCII 图画出工序流，**并在图上标出「现在在哪一步」**。

## 三、工序表
| 工序 | 干什么 | 状态 | 产出文件 |
| :-- | :-- | :-- | :-- |

## 四、当前位置
「现在在工序 N」+ **为什么是这里而不是别处**。

## 五、并行支线
| 支线 | 影响什么 | 是否影响主线 | 优先级 |
| :-- | :-- | :-- | :-- |

## 六、文件↔工序对照
库里每个文件属于哪道工序、一句话。

## 七、下一步
**只写一件事** + 它的输入清单（逐项标 ✅ 就位 / ⏳ 缺）。
```

---

## 七条铁律

1. **不许只给结论不给图** —— 凡涉及流程，必须有 ASCII 图或表格。
2. **每个工序必须标产出文件**（具体文件名）。没产出文件 = 这步没做完。
3. **状态只用 ✅ / ⬅️ / ⏳**，不许「部分完成」「基本完成」。
4. **「下一步」只能有一件事。** 列了多件 = 没想清楚优先级。
5. **必须回答「为什么现在能做 / 不能做」** —— 输入清单逐项标状态。
6. **新结论必须落盘成文件**，并在「文件↔工序对照」里登记。**只留在对话里的结论视为不存在。**
7. **不许说「见上文」** —— 每次汇报都要能独立看懂。

## 反例（出现任意一条即不合格）

```
✗ 分点罗列 10 条分析，没有整体图
✗ 说「方案见 A/B/C」，但不说它们在生产线哪个位置
✗ 只报「已完成」，不说产出落在哪个文件
✗ 下一步列 5 件事，没排优先级
✗ 用「部分完成」「基本可以」这类状态词
✗ 把结论写在对话里，不落盘
✗ 术语没翻译（幂等 / 归一化 / 上游下游 / 硬编码 …）
```

## 交之前自检

1. 抽一段 —— 通识教育的人读得懂吗？
2. 有没有没翻译的术语？
3. 有没有「这在全局的哪里」这一段？
4. 工序表每行都有产出文件吗？「下一步」只有一件事吗？

> 读完这份汇报，**一个没参与过的人**能不能回答：
> **目标是什么？现在在哪？下一步干什么？为什么能干了？**
> 四个问题有一个答不上，就是不合格，重写。
