# 决策记录模板（Decision Record）

> 用这个格式记录「为什么这么选」。**Prediction 必须在 Result 之前写**，事后补预测等于没预测。

---

## 复制以下内容

```markdown
## DR-NNN 一句话标题

- **日期**：
- **状态**：提议 / 已采纳 / 已取代（被 DR-XXX 取代） / 已废弃
- **谁定的**：（人名或角色）
- **影响面**：（小 / 中 / 大 —— 判据是「错一次多贵」）

### Decision（决定）
我们决定做什么。一句话，能被验收。

### Context（当时的情况）
做这个决定时已知什么、未知什么、有什么约束（时间、钱、人、外部依赖）。
**未知的部分要写出来** —— 那才是后人最需要知道的。

### Alternatives（还考虑过什么）
- 方案 A：…… 没选它是因为……
- 方案 B：…… 没选它是因为……
（至少两条。只写一条 = 没比较过。）

### Prediction（我预测会怎样）
**决定做出时**写下：预计发生什么、多久见效、什么信号说明它没成。
要写成**可观测**的（「两周内 X 指标降到 Y 以下」），不要写「应该会变好」。

### Result（实际怎样）
**后来**填。真实数字、真实结果。做不到就写「无法量化」+ 原因。

### Lesson（学到什么）
- 这次是**判断错**还是**执行错**？（两者要分开）
- 哪条模式要新增或修改？（指向 `references/pattern-library.md`）
- **防复发行动项 + 谁负责**：（没有行动项的教训 = 感想）

### 取代关系
若本条取代了旧记录：写明「取代 DR-XXX，因为……」。
**不要修改旧条目。**
```

---

## 三条硬规矩

1. **只追加，不修改。** 改主意就新开一条，写明取代谁。
2. **Prediction 在前，Result 在后。** 时间顺序错了，这份记录就没有学习价值。
3. **要能独立看懂。** 不许写「见上文」「同上」。
