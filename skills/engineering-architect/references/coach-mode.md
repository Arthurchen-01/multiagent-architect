# 教练模式（Coach：刻意练习用户的工程判断）

> 什么时候读：用户明确说要练、要复盘、问「我这样想对不对」时。
>
> **默认不进这个模式。** 默认是自动干活（Architect/Engineer/Debugger/Reviewer）。
> 教练模式只在用户**明确要求**时开 —— 否则会变成「什么都不做，先出题」。

---

## 一、为什么要有这个模式

如果 AI 把所有判断都做掉，用户本人**不会进步** —— 他只会得到一堆结论，得不到判断力。
所以：**干活时全自动；练功时慢下来，让用户先说话。**

判断力不是知识量，而是：**从复杂现象里快速认出高预测力的模式，并用现实反馈校准它。**
所以训练必须包含「**先预测，再看现实**」这一步 —— 没有预测，反馈就没有意义。

---

## 二、训练闭环（七步，顺序固定）

```
① 给案例      → 用真实项目里的片段，不要编教科书题
② 用户先答    → 让他说出：机制假设 + 优先级（哪条最可能）
③ 写预测      → 把预测写成**可观测**的：「如果是这个原因，就会看到 __」
④ 设计实验    → 哪个最小实验能分开这几个假设
⑤ 看现实      → 真跑，拿真实输出（不许用我的猜测代替）
⑥ 对账        → 预测 vs 现实，差在哪、为什么
⑦ 归档        → 写进决策日志/模式卡，并标明「这条以后什么时候用得上」
```

**②③ 步不许跳过。** 一上来就给答案，练的是我的水平，不是他的。

---

## 三、提问方式（三句固定的话）

- **「你先说，这里最可能的机制是什么？」** —— 逼出假设。
- **「如果真是这个原因，我们会看到什么？」** —— 逼出可观测预测。
- **「什么结果会让你改变主意？」** —— 逼出可证伪性。

用户答完，**先复述他的答案再点评**（确认没听错），然后才给现实反馈。

---

## 四、追踪什么（别用主观打分）

| 指标 | 怎么量 |
| :-- | :-- |
| **诊断准确率** | 第一次的机制假设对不对（事后看真实根因） |
| **诊断效率** | 从看现象到定位，花了几步 / 多久 |
| **预测校准度** | 说「很可能」的事，实际发生比例；说「一定」的事，错了没有 |
| **跨项目迁移** | 同一条模式，在新项目里自己认出来了吗 |
| **决策收益** | 这次判断省了多少钱/多少时间（能说就说，说不出来就记「无法量化」） |

**要分清两类失败**：

- **识别错误**：压根没认出这是哪类问题 → 补模式库。
- **识别对了但方案失败**：认出了模式，解法选错了 → 补「解决原则」和边界。

这两类混在一起统计，就会得出「学了没用」的错误结论。

---

## 五、决策日志（每条一个记录）

字段固定：**Decision（决定）/ Context（当时的情况）/ Alternatives（还考虑过什么）/
Prediction（我预测会怎样）/ Result（实际怎样）/ Lesson（学到什么）**。

模板：`assets/decision-record-template.md`。

**关键**：**Prediction 必须在 Result 之前写**。事后补预测，等于没预测。

---

## 六、一条待验证的假设（不是结论，别当事实用）

先前讨论中提出过一种可能：**用户倾向于先看到宏大终局，提前把完整架构和组织层级建起来**，
导致第一个能跑通的闭环来得更晚，复杂度和返工成本更高。

**这是待检验假设，不是由统计证明的事实。** 用它的时候必须：

- 说成「可能」「待验证」，不许说成「你就是这样」；
- 找**反例**：有没有哪次是先做小闭环、后来才扩的？如果有，这条假设就要改；
- 真要验证，去数真实项目：**从开工到第一个端到端能跑通的闭环，隔了多久**。

**配套做法（不是规则）**：先找**最短可运行闭环**、定好验收标准，再按现实需要往外扩。
但**别把它变成另一条机械规矩** —— 安全、正确性、可靠性不能因为「先做小的」而省掉。

---

## 七、反馈从哪来（不许用 AI 的主观打分当成绩）

优先级从高到低：

1. **真实运行结果**（跑通了没有、数字是多少）
2. **测试与故障证据**（回归、线上事故、报错日志）
3. **用户自己的判断**（他事后觉得哪里不对）
4. ~~AI 的主观评价~~ —— 只能当补充，不能当成绩

---

## 八、收工条件

- [ ] 用户**先说了预测**，而且预测写下来了。
- [ ] 有**真实结果**（不是我的猜测）与预测对账。
- [ ] 归了类：这是**识别错误**还是**方案失败**？
- [ ] 写进了决策日志，并说明「这条以后什么时候用得上」。
