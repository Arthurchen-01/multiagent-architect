# 诊断树（Debugger 模式）

> 什么时候读：坏了、慢了、反复出问题，或者要复核一个「已经定位好了」的结论时。
>
> **本文件只有一件事要做**：把「感觉不对」变成「可复现的一句话」，再沿着五层往下走，
> 每层都用**最小成本的区分性实验**确认，不靠猜。

---

## 一、先把现象写成一句话（不许跳过）

格式：**「在 __ 条件下，做 __，会得到 __（而不是 __）。」**

- 好：「在档案里已经有 1 条记录时，点选校页的按钮，页面无任何反应，控制台出现一条 404。」
- 坏：「按钮坏了。」「有时候不work。」「感觉不太对。」

写不出来，就说明**还没观察够**。回去看日志、看网络面板、复现一次。这一步花的时间，
通常在后面十倍地省回来。

**同时记录四条**：① 什么时候开始坏的 ② 之前改了什么 ③ 只在什么条件下出现 ④ 能不能稳定复现。
这四条里，「② 之前改了什么」是性价比最高的一条 —— 大部分故障都是最近一次改动的副作用。

---

## 二、五层诊断树（从上往下走，不要跳层）

| 层 | 要回答的问题 | 判错的典型表现 | 最小成本的区分性实验 |
| :-- | :-- | :-- | :-- |
| **1 信息** | 我看到的输入是对的吗？ | 数据本身就是坏的，却在下游查了一天 | 把**原始输入**原样打印/导出，肉眼确认一遍 |
| **2 理解** | 需求/任务本身理解对了吗？ | 做出来的东西「技术上没错，但不是人家要的」 | 用一句话复述需求，问「是不是这个意思」 |
| **3 决策** | 选的方案对吗？ | 方案本身就不成立，实现再完美也没用 | 换一个方案做**最小原型**，比结果 |
| **4 执行** | 实现/配置/部署对了吗？ | 代码对、配置错；本地对、线上错 | **两端并列打印**：本地 vs 线上、源码 vs 产物 |
| **5 验证** | 我的验收方式对吗？ | 验收本身有漏洞，所以「过了」但没修好 | 用**另一种口径**再验一次（换数据 / 换采样） |

**现实问题常常跨层。** 不要把它当互斥分类：一次故障可以同时是「理解错 + 验证有洞」。
五层是**提问顺序**，不是分类抽屉。

**走到哪层停？** 找到「如果这一层改对了，现象就消失」的那一层，就是根因层。
只能让它消失但不能解释为什么，那是**症状**，不是根因 —— 继续往下问一层。

---

## 三、区分性实验（这是本文件的核心技术）

**定义**：一个实验，如果两个候选假设的结果不同，才叫区分性；结果一样，就不值得做。

设计三步：

1. **列出候选假设**（2–4 个，按可能性排序，不要只列一个）。
2. **问：哪个观察结果能把它们分开？** 找不到 → 这个假设组合现在无法验证，先换一组。
3. **选成本最低的那个实验先做**（改一个变量、跑一次、看一个数）。

**对照实验的铁律**：**一次只改一个变量。** 同时改两处，即使好了也不知道是哪处起的作用。

**优先做「能证伪」的实验**，而不是「能证实」的：想证明「是这个原因」，就设计一个
「如果不是这个原因，它就不会这样」的观察。

---

## 四、常见弯路（踩过就别再踩）

| 弯路 | 为什么错 | 改成什么 |
| :-- | :-- | :-- |
| 先改代码再看现象 | 改了就没有干净基线了 | 先固定复现步骤，再动 |
| 加日志到处打，一次打十个 | 分不清哪个变量起作用 | 一次加一条能分开假设的日志 |
| 让模型「再想想为什么」 | 生成模型会编一个通顺的原因 | 用代码/命令去**量** |
| 只修症状（加重试、加兜底） | 复发，而且掩盖真因 | 先写清根因层，再决定要不要兜底 |
| 一次改三处「反正都可能是问题」 | 无法归因 | 一次一处，改完立刻验 |
| 把「重现不了」当「已经好了」 | 概率性故障最会骗人 | 提高复现频率（加压 / 改采样口径） |

---

## 五、出口条件（Debugger 模式什么时候算完）

必须同时满足：

- [ ] 现象那句话，现在**不再成立**（且我复现过它原本成立）。
- [ ] 我能说出**根因在哪一层**，以及**为什么**。
- [ ] 我做过一个**区分性实验**，它能排除至少一个候选假设。
- [ ] 修完之后，**原来好的地方没被弄坏**（跑一次回归）。
- [ ] 结论**落盘**：写进问题记录，带「防复发行动项 + 谁负责」。

**做不到第 2 条就明说「只修到症状层，根因未知」** —— 不要假装已经定位。
