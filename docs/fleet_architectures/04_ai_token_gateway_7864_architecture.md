# ⚡ AI 算力 Token 调度网关 (7864) 多服务器架构表

> **业务定位**：集中托管 256 个 WorkBuddy 官方账号池与 14 个 Google/Claude 凭证，向下游所有业务系统提供高可用、多模型聚合 API。

---

## 一、 跨机服务与出口网络拓扑

```
[你本机 / 业务端] ──(HTTPS/API)──► [五四云-1023 (香港 16C16G)]
                                          │
    ┌─────────────────────────────────────┴─────────────────────────────────────┐
    ▼                                                                           ▼
【链路 ①: wb2api 网关 :7864】                                      【链路 ③: Antigravity 容器】
- 账号池: 256 个 WorkBuddy 账号                                      - 账号数: 14 个 Google/Claude 凭据
- 模型: DeepSeek-V4.1, Gemini 3.5, Codex, Kimi                     - 模型: Gemini 3.8 Flash, Claude 3.7
- 出口: 香港直连机房 (8.7ms 到官方，超低延迟)                        - 出口: 日本独立 mihomo 代理 (脱离本机依赖)
- 调度策略: Response Time Weighted 动态加权轮询                     - 端口: :8045 / :8046 (API Key 分档裁剪)
```

## 二、 关键配置与性能调优基准表

| 参数名 | 历史错误值 | 生产优化标准值 | 优化 rationale |
| :--- | :--- | :--- | :--- |
| `max_in_flight` (单号并发) | 3 | **2** | 降低单账号撞上游 429 的风险概率 |
| `max_in_flight_global` (全局并发) | **2** ❌ *(严重偏低死穴)* | **活跃账号数 × 2** (约 200) | 彻底释放 256 个号的并行吞吐能力，消除首字延迟排队 |
| `breaker_threshold` (熔断阈值) | 8 | **8** | 连续失败 8 次触发断路，进入冷却 |
| `breaker_cooldown` (熔断冷却) | 30m ~ 6h | **30m ~ 6h** | 严禁缩短至几秒，避免在上游限制未解除时加剧封禁 |
| `idle_weight_max` (闲置加权) | 5.0 | **5.0** | 保证闲置号优先被调度，防止新号冷场 |

## 三、 出口脱钩与高可用防瘫痪改造

1. **根除本机 Windows 反向 SSH 隧道单点故障**：
   - 历史痛点：原日本出口通过本机 `verge-mihomo.exe` 经由 SSH -R 17890 穿透，本机一旦关机或网络抖动，云端 Antigravity 8045/8046 全盘挂死。
   - 改造方案：**在五四云-1023 上部署独立的 mihomo systemd 服务**，使用机房直连订阅（ikuuu 优先，仅放日本节点），与本地 Windows 彻底物理脱钩。
2. **账号健康度动态探活机制**：
   - 定时巡检脚本 `wbapi-n11-health` 自动探测各个账号 token 剩余额度；
   - 额度用尽时标记为 `COOLDOWN`，严禁物理删除账号文件，等待官方周期补充刷新。
