# 🎓 SAMURAI 留学申请系统多服务器架构表

> **业务定位**：全球名校留学项目、文书数据与录取标准自动化采集、解析与生成系统。  
> **涉及资产**：`41.7 万` 网页原始抓取归档（`samurai_raw.tar`, 8.66 GB）、多国大学数据库正本（3.0 GB）。

---

## 一、 跨机节点分工拓扑

| 节点名称 | 规格 | 角色与职责 | 核心目录 / 端口 | 防御与约束 |
| :--- | :--- | :--- | :--- | :--- |
| **花屿云-1024** | 16C32G | **任务中心 (Brain)** + 归档中枢 | `/opt/samurai-tc` (:8790)<br>`/opt/samurai-admission/raw-archive/` | 严禁将 8.66GB 归档留在 `/tmp`，已迁移至受控持久化目录 |
| **五四云-1023** | 16C16G | **数据库正本 (SSOT)** | `/opt/samurai-admission/Database` (3.0 GB) | 作为数据唯一真本，定期生成只读 SQLite 快照，供 Worker 同步 |
| **小特云-待补** | 16C16G | **离线 NLP 分词与清洗** | `/opt/samurai-nlp/` | 北京 NAT 节点，无国际出口，专职跑 CPU 密集型文档向量化与清洗 |
| **五四云-1021** | 16C16G | **爬虫采集分片** | `/opt/samurai-crawl/` | 国际网络出口节点，按大洲与国家划分分片抓取 |

## 三、 历史死穴与刚性防御规则

1. **磁盘溢出防爆死穴**：
   - 历史痛点：大量 `.html.gz` 和中间临时文件直接落盘在 `/tmp`，导致花屿云 `/tmp` 暴涨至 24 GB。
   - 防御守卫：**必须在爬虫端配置流式落盘与自动压缩归档**，并挂载专用存储卷；每日由定时任务执行 `vacuum`。
2. **多节点重复抓取死穴**：
   - 历史痛点：缺乏任务认领锁，两台节点同时爬取多伦多大学/早稻田大学同一站点，触发目标网站 WAF 封禁。
   - 防御守卫：**严格执行 `tasks/pending/` 状态机排他锁**，基于目标站域名生成 Hash 分片分配给固定节点。
