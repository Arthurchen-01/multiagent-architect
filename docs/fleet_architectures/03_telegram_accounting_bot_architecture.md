# 🤖 Telegram 记账与自动履约机器人多服务器架构表

> **业务定位**：基于 Telegram Bot 接收用户充值、卡密核销、账单查询与财务记账，自动分发 Token/账号与自动化履约。

---

## 一、 跨机节点分工拓扑

| 节点名称 | 规格 | 角色与职责 | 核心端口与安全措施 |
| :--- | :--- | :--- | :--- |
| **量芯云-1030** | 4C8G | **Telegram Bot 主控节点** + 财务数据库 | **SSH 监听 22222 端口**（改默认端口防爆破）<br>Bot 轮询守护进程 `tg_bot.service`<br>SQLite/PostgreSQL 记账账本 |
| **五四云-1023** | 16C16G | **库存与履约网关** | 监听 7864 端口，提供可用账号与 Token 查询 |
| **量芯云-1011** | 4C4G | **闲鱼履约发货分片** | 监听订单事件，自动发送卡密凭据 |

## 二、 关键数据流与幂等性保障

```
 Telegram 客户端 ──► [量芯云-1030 :22222 (TG Bot)]
                           │
                           ├── 1. 验证用户指令与签名
                           ├── 2. 检查幂等性流水账 (Idempotency Key: {chat_id}_{msg_id})
                           │      └─ 若已处理 ──► 直接返回历史结果，防重复扣款！
                           │
                           ├── 3. 调用库存网关核销卡密 ──► [五四云-1023 (网关 7864)]
                           │                                  │
                           │                                  ▼ 扣减库存
                           │                              生成独立 API Key
                           │                                  │
                           ├── 4. 写入本地账本事务落盘 ◄───────┘
                           └── 5. 消息回传用户：交付卡密凭证
```

---

## 三、 刚性防御守卫与防 Bug 机制

1. **分布式幂等性守卫 (Anti-Double-Spend)**：
   - 所有的转账、核销、记账操作，必须在数据库中建立 `unique_index(transaction_hash)`；
   - 严禁在网络超时时盲目重发交易，必须先查流水再补发。
2. **安全与跳板机隔离**：
   - 量芯云-1030 承担生产跳板机角色，除 22222 SSH 端口外，其他管理端口一律不对公网暴露；
   - Bot Token 采用环境变量隔离注入，严禁硬编码进代码仓库。
