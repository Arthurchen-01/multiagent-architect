# 🏛️ 全机队产品意志、业务边界与权责仲裁规约 (Product Requirements & Arbiter Gate)

> **法定产品与架构最高基准**
> - **适用范围**：`Arthurchen-01` 旗下全机队、全仓库、全智能体（WorkBuddy, DeepSeek Harness, Antigravity, Roo Code, CodeBuddy 等）
> - **基准定位**：**Spec 是源代码，PRD 是不可篡改的商业锚点**。任何智能体进入本项目，必须强制加载并无条件遵守本规约。

## 一、 角色权限与决策权分工（谁决定什么）

系统严格执行三权分立与所有权分级，严禁角色僭越与反向甩锅：

| 角色 | 实体 | 拥有法定决策权的事项 (Decisions) | 绝对禁止越权的事项 (Prohibited) |
| :--- | :--- | :--- | :--- |
| **所有者 / 商业方 (Owner)** | **用户 (人类老板)** | 1. 业务最终目标与指标（如日产 100 个成品）；<br>2. 资金预算与充值额度（如 ¥200/天，单号 ¥2.00 目标）；<br>3. 调度启停指令（跑够 N 个即停、配额任务下达、通道优先级偏好）。 | 无（拥有系统最高裁决权）。 |
| **架构师 / 仲裁官 (Arbiter)** | **架构总控 (MultiAgent Architect)** | 1. **系统刚性不变量 (Invariants)** 的制定与死守（鲜度闸、背压机制、零直连、资金守恒）；<br>2. 审核与裁决工程师的方案，拒绝任何违背 Invariant 的提交；<br>3. 跨机队代码一致性 (FleetSync SHA-256) 验证。 | 严禁降低 Owner 设定的商业指标；严禁将底层工程 Invariant 伪装成商业选择反向甩给 Owner 拍板。 |
| **工程执行者 (Engineer)** | **WorkBuddy / AI Workers** | 1. 业务逻辑编写与 Bug 修复；<br>2. 供应商接口适配与多供货线平滑熔断切换；<br>3. 配额控制器与自动化任务闭环执行；<br>4. 资金对账与日志留痕。 | **严禁私自修改 PRD/Spec**；严禁以“当前达不到”为由篡改业务指标；严禁在生产机器进行 Ad-hoc 私修。 |
| **独立评审员 (Reviewer)** | **Reviewer Agents / 自动化测试** | 1. 物理核对生产产出与真核执行证据 (Proof-of-Execution)；<br>2. 验证资金守恒等式与账本对账流水；<br>3. 运行本地自动化测试套件 (`python tests/run_tests.py`)。 | 严禁采信无凭证的口头汇报或假数据 (如 backfill 假成品)。 |

## 二、 用户核心产品要求与终态呈现（刚性产品铁律）

### 1. 配额任务与“跑够即停”语义 (Quota-and-Stop Pattern)
* **启停时间戳**：任何配额任务必须以**用户下达/点击开始指令的时间戳 $T_0$** 作为唯一起始基线，严禁以当日 00:00 或历史数据混淆。
* **增量产出判定**：目标达成以 $T_0$ 之后新增的**真实可用有效成品数量 $\Delta S$** 为准（必须通过网关 HTTP 200 验证，严禁回填历史 `backfill:git` 数据冒充）。
* **自动熔断停买**：一旦 $\Delta S \ge \text{Target}$：
  1. 立即下发信号切断外部采购接口，**停止买号**；
  2. 队列中已存在的在途账号平滑消化完毕（若超时则按鲜度闸作废）；
  3. 释放 worker 进程，进入常驻待命状态；
  4. 向控制台推送完成报告。

### 2. 节奏控制：20 秒稳定轮询 (Steady Polling)
* 系统必须维持恒定、平滑的慢速工业节奏（默认 20 秒/次检查轮询），严禁无节制的野蛮并发冲击，确保代理通道、打码接口与号机稳定运行。

### 3. 鲜度守卫与背压联动 (Freshness & Backpressure) —— 资金不打水漂的核心
* **即买即跑铁律**：严禁“先把号买下来囤在账本里慢慢跑”！
* **背压阻断逻辑**：
  $$\text{允许进货条件} \iff \text{当前待跑队列数} < \text{机队空闲 Worker 数}$$
  若无空闲 Worker，采购管道**物理闭锁**，绝不预支进货。
* **60 分钟鲜度硬超时**：
  - 采购入库必须写入 `bought_at` 毫秒级时间戳；
  - 超过 30 分钟未被 Worker 认领的账号发出告警；
  - 超过 60 分钟强制标记 `EXPIRED_UNRUN`（绝不送入自动化浏览器，杜绝 91% 撞手机墙与徒劳消耗代理）。

### 4. 资金与账本绝对守恒律 (Wallet Reconciliation Invariant)
* 每一笔采购必须在本地形成具有事务唯一性的流水记录：
  $$\text{供应商扣费金额} \equiv \sum \text{成功采购记录} + \text{异常未履约冻结}$$
* 系统每小时自动拉取外部钱包账单对账，一旦出现漏记账（如历史上的 32 个号 / ¥56 漏账），立即熔断阻断进货并向控制台报警。

## 三、 七条系统级“绝对不许”红线 (Systemic Invariants)

1. **不许私改 PRD**：PRD 是人类老板立的法，只有老板能改。AI 跑不出指标是能力问题，必须改代码，严禁改指标。
2. **不许拿假数字当成就感**：严禁将 Git 历史回填 (`backfill:git`)、测试假号算作当日生产成品。
3. **不许单机 Ad-hoc 私修**：禁止在单台服务器上手动修改生产代码。任何改动必须进 Git，经测试套件验证后通过 `FleetSync` SHA-256 跨机对齐发布。
4. **不许黑盒自留 Skill**：禁止把产品规约写在某个 AI 的私有本地目录（如 `~/.workbuddy-ai/...`），所有规约必须进主干 `.spec/`，全机队所有 Agent 共享。
5. **不许在底层工程 Invariant 上反向甩锅**：“修不修鲜度闸”、“要不要背压”是工程架构的自律义务，绝不是扔给老板选的商业单选题。
6. **不许无证据口头宣布完成**：所有产出汇报必须提供外部凭证（CF-RAY、时间戳、供应商 Order ID、物理截屏快照）。
7. **不许断料时让机器空转**：供货线断货或没钱时，系统必须优雅进入休眠挂起（Suspend），严禁死循环刷日志抢占 CPU。
