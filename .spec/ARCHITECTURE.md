# 🏛️ MultiAgent Architect: 架构白皮书与系统工程规范

## 一、 系统核心哲学：从“随缘对话”到“工业编译”

现代软件工程在引入大模型（LLM）后，经历了三个关键范式转移：

```
时代 1：网页对话时代 (2022~2023)
  - 模式: 复制粘贴，问答式打字员。
  - 瓶颈: 上下文割裂、无感知仓库结构、粘贴疲劳。

时代 2：IDE Agent 时代 (2023~2024)
  - 模式: Cursor / Claude Code 直接读写本地代码。
  - 致命绝症: 
    1. Review 疲劳 (人类眼球跟不上 AI 生成速度);
    2. 意图丢失 (需求散落在聊天记录里，Git 中无 trace);
    3. 一致性崩塌 (多轮对话导致上下文腐败、架构裂变)。

时代 3：规范驱动开发 (SDD) 与分布式多智能体架构 (2025~未来)
  - 核心定义: Spec 是源代码，代码是编译产物。
  - 协作关系: 人类与需求打交道，AI 与代码打交道。
  - 运行底座: 状态机任务总线 + 3审1裁仲裁流水线 + 分布式防脑补真核审计。
```

---

## 二、 核心架构支柱

### 1. 意图物理进 Git（Spec-as-Source）
所有的系统架构、API 契约、数据结构与刚性不变量（Invariants）必须首先物理落盘在 `.spec/SPEC.md` 中。**严禁在没有 Spec 的情况下直接编写业务逻辑。**

### 2. 状态机解耦与并发防抢占（State Machine & Atomic Claiming）
在多窗口（多个 IDE 终端）与多服务器（跨机节点）并行作业时：
* 任务池划分为 `tasks/pending/`、`tasks/running/`、`tasks/done/`。
* 任何 Worker 认领任务必须通过原子文件重命名操作加锁（`{worker_id}-{task_id}.md`），杜绝任务重复执行和状态竞争。
* 任务结束必须通过“自动化退出守卫（Exit Guard）”将测试结果和 SHA-256 签名写回任务卡，并原子转移到 `tasks/done/`。

### 3. 三权分立与总裁判仲裁（Tri-Review & Arbiter Pipeline）
对于高危、复杂模块（L3 级别）：
* **安全审计员 (Security Guard)**：专项扫描注入、鉴权缺陷、Token 泄露。
* **并发性能审计员 (Performance Guru)**：专项排查死锁、慢 SQL、内存泄漏、竞争冒险。
* **业务不变量审计员 (Invariant Checker)**：专项验证业务数学守恒等式与状态闭环。
* **终审仲裁官 (Arbiter)**：解决审核员之间的诉求冲突，发布机器唯一判决。

### 4. 真核执行证据链（Proof-of-Execution）
彻底根除大模型“伪造执行、凭空编造爬虫结果、虚假测试成功”的弊端：
* **外部不可预测头**：校验 Cloudflare `cf-ray` 与毫秒级 `Date`。
* **原生报文密码学哈希**：抓取原始数据必须 gzip 落盘并校验 SHA-256。
* **内核网络连接套接字**：读取 Linux 内核 `/proc/<PID>/net/tcp` 验证对外真实物理 TCP 握手。
* **DOM 真实截屏与坐标**：真实渲染高精 PNG 截图。
